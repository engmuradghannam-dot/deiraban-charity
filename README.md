# منصة جمعية ديرابان الخيرية

منصة عربية RTL مبنية بـ Django REST Framework وReact لخدمة عضوية الجمعية، وتنظيم الانتخابات الداخلية، وإدارة طلبات التبرع.

## ما يتضمنه النظام

- **العضوية والتحقق:** تسجيل دخول Google، وربط حساب العضو برقم العضوية والاسم واسم العائلة كما وردت في سجل الجمعية. يبقى الطلب معلقاً حتى اعتماد الإدارة من Django Admin.
- **الانتخابات:** عرض الانتخابات والمرشحين، وتسجيل ورقة واحدة لكل عضو فاعل معتمد في كل انتخابات مفتوحة. يحفظ النظام سجل المشاركة منفصلاً عن ورقة الاقتراع ولا يضع هوية العضو على الورقة؛ تعرض لوحة الإدارة مجاميع المشاركة والنتائج فقط. تكون النتائج مخفية أثناء الانتخاب افتراضياً، ويمكن للإدارة إعلانها.
- **التبرعات:** عرض الحملات النشطة، وتسجيل طلب مساهمة نقدية أو حوالة بنكية، ومتابعة سجل المتبرع المسجل. تظل الطلبات بانتظار التحقق حتى يؤكد أمين الصندوق الاستلام من Django Admin؛ لا توجد بوابة دفع إلكتروني ولا يُخصم أي مبلغ من الموقع.
- **الخصوصية الإدارية:** بيانات سجل العضوية المستورد متاحة لمسؤولي الجمعية فقط. لا تتيح لوحة الإدارة إنشاء ورقة اقتراع أو تعديلها أو حذفها.

## تشغيل الواجهة الخلفية محلياً

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python manage.py migrate
python manage.py import_members
python manage.py createsuperuser
python manage.py runserver
```

تعمل واجهات API على `http://127.0.0.1:8000/api/`، ولوحة الإدارة على `http://127.0.0.1:8000/admin/`.

## تشغيل الواجهة الأمامية

```bash
cd frontend
npm install
cp .env.example .env
npm run dev
```

تعمل الواجهة على `http://localhost:5173`. املأ `VITE_GOOGLE_CLIENT_ID` في `.env` لإظهار تسجيل الدخول عبر Google. يمرر Vite طلبات `/api` إلى Django محلياً.

## تهيئة Google OAuth

أنشئ OAuth Client من Google Cloud Console. اضبط `GOOGLE_CLIENT_ID` و`GOOGLE_CLIENT_SECRET` و`GOOGLE_CALLBACK_URL` في بيئة Django، وأضف النطاق المحلي أو نطاق النشر إلى أصول JavaScript المعتمدة في إعداد Google. استخدم القيمة نفسها لـ `GOOGLE_CLIENT_ID` في الواجهة.

## تجهيز بيانات النظام

1. شغّل `python manage.py migrate` لإنشاء مخططات سجل الأعضاء والحسابات والانتخابات والتبرعات.
2. شغّل `python manage.py import_members` لاستيراد سجل العضوية من `data/members.csv`.
3. أنشئ مستخدم إدارة عبر `createsuperuser`.
4. من لوحة الإدارة، أنشئ الانتخابات وحدد المرشحين ومواعيد الاقتراع، وأنشئ حملات التبرع.
5. راجع طلبات ربط العضوية واعتمدها. يجب أن يطابق رقم العضوية والاسم واسم العائلة السجل الرسمي.
6. أكد التبرعات المستلمة من لوحة الإدارة؛ وحدها الحالات المؤكدة تظهر في إجمالي الحملة.

## النشر

يدعم Django قاعدة `DATABASE_URL` (PostgreSQL عند النشر) ويعود إلى SQLite للتطوير المحلي. قبل النشر، وفّر قاعدة بيانات دائمة، ومفتاح `DJANGO_SECRET_KEY` قوياً، وبيانات Google OAuth، ونطاق الواجهة في `CORS_ALLOWED_ORIGINS`، ورابط API الكامل في `VITE_API_URL`. لا تستخدم SQLite على خدمة ذات نظام ملفات مؤقت لتخزين سجلات المشاركة وأوراق الاقتراع والتبرعات.

يهيئ `render.yaml` الخدمات ومتغيرات البيئة المطلوبة، لكنه لا ينشئ حساب Google OAuth أو قاعدة بيانات خارجية نيابة عنك. بيانات الحساب البنكي أو تعليمات تسليم النقد لم تُضف في الكود؛ يزوّد أمين الصندوق المتبرعين بها خارج الموقع. الصور المرفوعة للمرشحين تحتاج تخزين ملفات دائم إذا استُخدمت في الإنتاج.
